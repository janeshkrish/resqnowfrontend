# Updater bootstrap with Mappls temporarily disabled

Owner approved this release scope on 24 November 2026: publish the signed updater-enabled app for new website installers, with native Mappls temporarily disabled and its implementation preserved. Old APK migration is out of scope. Existing in-app update consent, integrity, version, signing and work-deferral safeguards remain mandatory.

Use a reversible `VITE_NATIVE_MAPPLS_ENABLED=false` / `RESQNOW_MAPPLS_ENABLED=false` build setting. Missing settings preserve the current enabled behavior. Reject malformed or contradictory settings. In disabled Android builds, show an intentional unavailable-map message, invoke no native map/search operations, do not register the native map plugin, and do not require/apply native Mappls registration files. Preserve all map source/dependencies and normal web maps. Enabled releases must still require the approved native pair. All release modes still require the original signing identity, production public settings, enabled updater and increasing version code.

Preserve address selection through the already-existing backend Photon search only in the disabled Android mode, without native Mappls calls or fabricated provider IDs. A selected destination must still satisfy the unchanged coordinate/quote gate before Continue. Explicit no-ID replacement clears prior pickup/drop IDs; coordinate-only updates with an omitted ID retain existing semantics. Emit the native/updater/map build mode from Vite, validate the actual synced artifact before every real Gradle release producer, and verify the same marker inside the final APK. Process environment agreement alone cannot qualify cached web output.

Build and verify before replacing delivery. Prefer local secure signing: no signing-key/password/license upload to GitHub, no secrets in command arguments, source or logs. Reconfirm current GitHub history and the owner-attested distributed version ceiling7 before allocating a higher version. Publish only a verified public APK and matching release manifest to the approved GitHub repository. Enable website release downloads/update discovery on the correct Railway production service only after public release validation, then verify both endpoints. Do not enable unattended installation or future automatic publication flags as a side effect.

Completion means the website serves the same verified updater-enabled signed artifact, production discovery offers its matching manifest, and subsequent newer same-signature release delivery has been validated. Tests with synthetic keys do not establish production signer continuity. Secure user password entry and any unavailable production access remain explicit blockers; never replace them with test credentials or a new key.
